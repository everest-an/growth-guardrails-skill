# 示例:把 ABP/360 手法映射为合规方案

> 脱敏说明:本示例基于一个真实产品的获客方案改写——"边缘 AI 模型运行时分发"(模型分发=获客层,商业产品=变现层)。
> 具体产品名、数据、路线图均已去除,只保留可复用的**手法映射方法论**。
> 更新:2026-08-28

---

## 场景

你有一个**免费/开源的边缘 AI 运行时**(0.4MB 级,可跑在 MCU 级硬件),和一个需要变现的商业产品。
核心战略判断:**最大获客杠杆不是抢流量,而是让你的运行时成为边缘设备的"默认 AI 运行时";商业产品是变现层,运行时分发是获客层。**

## 资产盘点(获客起点)

| 资产 | 获客价值 | 对应手法内核 |
|---|---|---|
| 浏览器在线 Demo | 零门槛体验,无需下载 | 默认选项优化 |
| 开源主仓库(MIT) | 开发者信任 + 自然流量 | OEM 预装的信任背书 |
| 中英双语技术论文 + 模型/包页 | SEO + 学术信用 | 渠道点位 |
| 商业产品免费试用 | 变现入口 | 家族产品交叉引流出口 |
| 独家技术卖点(体积/功耗) | 差异化真空带 | 大厂不做、小厂做不到 |

## 手法映射表(ABP/360 原手法 → 合规变体)

| # | ABP/360 原手法 | 合规变体(映射) | 实施要点 | 红线(禁止) |
|---|---|---|---|---|
| 1 | 捆绑分发(ABP 经下载站/默认勾选) | **依赖式分发**:包管理器收录(runtime 进 Ollama/pip/npm/Homebrew 库),`pull/install` 即触达;模型页/README 挂商业产品 CTA | 装依赖即获客,免费且合法 | 安装器强制勾选/隐藏捆绑(工信部零容忍) |
| 2 | OEM 预装(Opera×厂商) | **硬件渠道预置**:开发板镜像(树莓派/Jetson/Orange Pi)预置运行时;芯片厂 SDK/示例库收录;找系统集成商(SI)做行业方案捆绑(电池管理/可穿戴/车载) | 一个镜像触达整批开发者;可卸载/可选是前提 | 预装不可卸载(2023 通告)、广告注入 |
| 3 | 默认设置抢占(360 改 hao360) | **零摩擦默认值**(产品内):IDE 插件默认启用;包管理器一键装(winget/choco/brew)= 现代版"出厂预装";在线 Demo 默认 CTA 导向下载 | 默认值 = 用户利益,且随时可改 | 未经选择篡改用户默认设置 |
| 4 | 恐吓弹窗(360"高危漏洞一键修复") | **价值正向提醒**:试用到期文案改为"你的项目已完成 X 个任务,升级解锁全部功能" | 制造完成感,不制造焦虑;转化率同样高,零法律风险 | 虚构威胁、虚假倒计时 |
| 5 | 家族交叉引流(360 全家桶) | **开源 ↔ 商业闭环**:每个开源 repo README 顶部 Live Demo → 商业产品下载;Release 页挂 CTA;GitHub Actions 模板让开发者"一行命令"接触产品 | 每个开源入口都是获客触点 | 诱导卸载竞品、强制不兼容 |
| 6 | 商店推荐位(ABP 头部曝光) | **插件市场 / 模型库榜单**:真实下载量与好评触发推荐位,马太效应 | 质量驱动,不用买量 | 刷榜、虚假评分 |

## 渠道落点(中文市场示例)

| 渠道 | 动作 | 优先级 |
|---|---|---|
| 搜索资源平台 | 站点收录 + sitemap | 高 |

## 关键指标(漏斗)

- **分发层**:包管理器 pulls / 模型页 downloads / GitHub stars(衡量"预装"触达)
- **产品层**:Demo 试玩 → 商业产品下载转化率(目标 >10%)
- **变现层**:免费试用 → 付费转化率

## 方法论要点

1. **手法内核可复用,皮不可复用**:捆绑的"内核"是"在用户必经之路上出现",合规的皮是"包管理器收录/依赖即触达";恐吓的"内核"是"制造紧迫感",合规的皮是"制造完成感"。
2. **变现层永远比分发层多一次曝光**:每个分发触点都要指向变现入口,但入口本身必须是用户利益(工具、体验、内容)。
3. **独家卖点是最大护城河**:选一个"大厂不做、小厂做不到"的真空带做默认生态位——比任何捆绑都持久。
